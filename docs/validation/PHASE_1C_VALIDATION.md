## Boundaries implemented

Single-use hashed random OAuth state is session/connection-version bound and expires after ten minutes. `/auth/google/callback` uses the exact configured APP_ORIGIN; codes/state are never reflected, callback access logs are disabled. Only `gmail.readonly` and the dedicated `aban.hackathon@gmail.com` mailbox are accepted. Tokens stay encrypted in PostgreSQL with a named Fernet key version. Refresh/key rotation uses a credential-revision comparison after network work; disconnect/reconnect/session expiry cannot restore removed credentials. Removing an old key requires reconnection when its tokens cannot decrypt. Missing configuration leaves the UI honestly disabled.

Connect does not scan. An explicit report fingerprint/window confirmation creates one expiring durable operation (20 minutes). Reports are limited to 31 days; UTC search starts 90 days before start and ends exclusively at midnight eight days after end (includes seven whole following days). At most 15 candidate message IDs, ten imported files and 40 MiB per operation, plus shared 10 MiB/ten-page validity limits. Arrival is not expense date: all Gmail evidence is review-required. Body-only/unsupported files, empty, denied, wrong account, revoked, permission/quota/outage, partial and truncated outcomes remain distinguishable. There is no monitoring, sending or modifying mail.

Shared `persist_checked` storage preserves the existing owner/hash dedup, original bytes, links and evidence-validation jobs; Gmail provenance is server-only in `gmail_imports` (mailbox/message/attachment/received/import IDs and hash). Each successful attachment is checkpointed atomically. Crashes/retries reuse exact attachment identities and hashes. Search pagination truncation does not stop at the first candidate; exact file limits alone do not imply additional omitted evidence.

No session/document transaction or row lock spans OAuth/Gmail/file parsing. Short authority reads precede external work; fresh session/persona/expiry/report fingerprint/consent/connection/lease checks protect every result write. Worker claims commit before calls, reclaim expired leases, cap three attempts per checkpoint and apply bounded backoff. Provider requests have connect/read deadlines and a 15s streaming bound; operation scheduling is bounded at 330s with a 360s lease. Stale results cannot write. Sequential worker cleanup removes expired-session encrypted credentials; keep the worker running. Disconnect immediately removes local credentials/cancels future scans and attempts provider revocation; a revocation failure is reported separately. Retained evidence requires explicit owner database cleanup; no silent purge.

Demo runtime caps are enforced: four concurrent manual uploads per web process; 100 documents/100 MiB per session and 1,000 documents/1 GiB globally, serialized during persistence; 1,000 total sessions; 50 reports and 50 scan operations per session. Dedup reuses stored bytes at capacity. These bounds stop anonymous unbounded DB growth; they are not production capacity/performance measurements. Expired evidence continues to consume storage until owner cleanup.

Migration `0004_phase1c_gmail` adds only connections, OAuth states, scans/import provenance and Gmail link source. Downgrade removes Gmail-only tables/links but preserves original documents/bytes and manual evidence. No expense/submission/approval schema.
